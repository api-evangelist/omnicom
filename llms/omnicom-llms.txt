## API surface

Omnicom publishes **no public API**. As of the 2026-08-12 probe there is no
developer portal, no API reference, no OpenAPI/Swagger/AsyncAPI/GraphQL
document, no first-party SDK on npm, PyPI or any other public registry, no
public MCP server, and no A2A agent card on any Omnicom host.

Contract discovery was run against every host the company controls:

- `www.omc.com` — WordPress corporate site. `/openapi.json`, `/swagger.json`,
  `/api-docs`, `/llms.txt`, `/security.txt` and every `/.well-known/*` path
  return HTTP 404. `/wp-json/` returns HTTP 403 (WAF), so even the CMS API is
  closed.
- `omni.omc.com` — the Omni platform. An Angular single-page application behind
  Imperva that 301-redirects every unknown path to `/home/` and then serves the
  same HTML shell with HTTP 200. Every 200 on this host is a catch-all, not a
  document; `/openapi.json`, `/graphql`, `/.well-known/agent-card.json` and
  `/.well-known/agent.json` all return that shell.
- `api.omc.com`, `developer.omc.com`, `docs.omc.com`, `platform.omc.com` — do
  not resolve in DNS.
- `www.omnicomgroup.com` — the legacy corporate domain; 301-redirects to
  `www.omc.com`.

The Omni product page describes the platform as "interoperable by design" and
Omnicom has publicly announced integrations it *consumes* (Instacart Developer
Platform, The Trade Desk, InfoSum, Affinity Solutions), but the platform's own
programmatic surface is delivered to agencies and clients rather than published.
